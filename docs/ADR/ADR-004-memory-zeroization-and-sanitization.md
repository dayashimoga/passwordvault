# ADR-004: Memory Zeroization, Locking, and Hygiene Strategy

## Status
**Decided / Accepted**

## Date
2026-10-19

## Context
In memory-managed and modern preemptive operating systems, plaintext cryptographic secrets risk leaking into:
1. Process heap and stack memory lingering long after variables drop out of scope.
2. OS swap files, paging files, or hibernation images on disk.
3. Crash dump reports generated by the OS or user-space crash handlers.
4. Process core dumps inspectable by other local processes or unprivileged users.

## Decisions

### 1. Compile-Time and Drop Zeroization
- All sensitive keys (`MasterKey`, `DataKey`, `BiometricKey`, `RecoveryKey`, `Passphrase`, and decrypted `Item` fields) must wrap inner buffers in `zeroize::Zeroizing<T>` or implement `zeroize::Zeroize` and `zeroize::ZeroizeOnDrop`.
- Intermediate buffers allocated during Argon2id KDF hashing or AEAD decryption are immediately zeroized upon completion.

### 2. OS-Level Memory Locking (`VirtualLock` / `mlock`)
- Where allowed by OS security policies and privileges:
  - On Windows: Use `VirtualLock` to lock the session memory containing the active `DataKey` to prevent the OS memory manager from paging the secret to `pagefile.sys`.
  - On Linux / Android / macOS: Use `mlock` to pin secret memory pages into physical RAM.
- Graceful degradation: If `mlock` or `VirtualLock` returns an error (e.g. `RLIMIT_MEMLOCK` exceeded or unprivileged context), the application logs an internal warning and proceeds with heap zeroization, never failing to run or crashing the user's application.

### 3. Crash Dumps and Core Dumps
- Disable automated full-memory crash dumps on Windows using `SetProcessMitigationPolicy` (`ProcessImageLoadPolicy` and `ProcessMitigationOptions`).
- On Linux/macOS: Disable core dumps via `prctl(PR_SET_DUMPABLE, 0)` and `setrlimit(RLIMIT_CORE, 0)`.

### 4. Managed Runtime Limitations Disclosure
- Dart (the Flutter runtime) utilizes a generational garbage collector with string deduplication and compaction. Dart strings cannot be pinned or zeroized with hardware guarantees.
- To mitigate this runtime limitation:
  - Secrets are kept in Dart memory for the minimum necessary duration (only while actively rendered on screen).
  - Search queries and metadata operate on tokens without holding long-lived plaintext strings in Flutter state.
  - When the vault locks or the app is minimized, Flutter providers immediately clear and garbage-collect all item viewmodels.

## Consequences
- **Positive:** Massive reduction in residual memory footprint and near-zero risk of plaintext keys persisting on disk via paging or crash dumps.
- **Negative:** Managed Dart runtime cannot guarantee 100% immediate zeroization of UI text controllers; documented honestly as a platform constraint.
